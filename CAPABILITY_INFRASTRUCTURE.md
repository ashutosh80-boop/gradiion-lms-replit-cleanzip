# CAPABILITY INFRASTRUCTURE

## Core Principle

Every meaningful student action must create capability evidence, not just completion.

The GRADIION LMS is not a course platform. It is the operating foundation for capability formation, correction, verification, and portable institutional records.

## Capability Domains

GRADIION capability evidence should map to six core domains:

- Clarity
- Communication
- Decision-Making
- Execution
- Professional Presence
- Composure

## Evidence Types

Evidence items may come from multiple learning, testing, application, and correction moments:

- Baseline Diagnostic
- Decision Check
- Scenario Judgment Drill
- GCP Video Response
- GCP Audio Response
- GCP Written Response
- Field Application
- Field Execution Report
- Correction Resubmission
- Capstone Response

## Submission Statuses

Capability evidence should support the following statuses:

- Draft
- Submitted
- Pending Review
- Approved
- Correction Required
- Resubmitted
- Rejected / Not Yet Acceptable
- Verified

## Evidence Metadata

Every evidence item should eventually store:

- student ID
- phase
- module
- lecture
- evidence type
- capability domains tested
- prompt/question
- response/transcript/file reference
- timestamp
- status
- reviewer notes
- AI review notes
- correction note
- resubmission history
- verification status

## GCP Structure

The future Gradiion Capability Profile is an evidence-based record, not a gamified progress page.

It should include:

- capability domains
- evidence items
- correction history
- resubmissions
- verified records
- current capability standing
- no badges
- no points
- no gamified percentages

The GCP should answer: what capability has this student demonstrated, where was it tested, what required correction, and what has been verified?

## GCS Structure

The future Gradiion Capability Score is a scored interpretation of verified evidence across the six capability domains.

Future scoring logic should account for:

- capability score per domain
- overall capability readiness
- repeated failure patterns
- correction density
- verification status

GCS should not reward activity volume. It should interpret evidence quality, correction response, consistency under pressure, and verified capability readiness.

## Capability Passport

The future Gradiion Capability Passport is a portable verified capability record built only from approved or verified evidence.

It should eventually include:

- verified baseline
- completed modules
- reviewed GCP responses
- resolved corrections
- capstone result
- capability domain evidence
- verification timestamps

The passport should be portable, serious, and institution-ready. It should not resemble a certificate gallery or badge wallet.

## Organizational / Government Use

The same evidence structure can later support:

- team capability dashboards
- organizational readiness audits
- role readiness checks
- correction density reports
- institutional capability verification
- government capability readiness records

This requires consistent evidence metadata, review status, correction history, domain mapping, and verification logic from the beginning.

## Build Rules

All future LMS features must preserve this chain:

Evidence -> Review -> Correction -> Resubmission -> Verification -> GCP -> GCS -> Passport

Features that only mark completion without creating evidence should be treated as incomplete infrastructure.
